# Безопасное применение миграций Prisma

Не удаляйте строки из `_prisma_migrations` вручную: это может привести к повторному применению миграций и повреждению схемы.

1. Сделайте резервную копию PostgreSQL.
2. Проверьте состояние: `docker compose ps` и `docker compose logs migrate`.
3. Запустите миграции через одноразовый сервис: `docker compose run --rm migrate`.
4. Если миграция отмечена как failed, сначала изучите ошибку и сравните схему БД с SQL миграции. Не очищайте таблицу миграций целиком.
5. После успешного завершения проверьте `docker compose ps` и доступность `http://localhost:5001/api/health`.

Backend доступен только внутри сети Docker и не публикует порт 4000 на хост.

В системе нет стандартных паролей. Для первичного создания администратора задайте временный `BOOTSTRAP_ADMIN_PASSWORD` длиной не менее 12 символов, запустите миграции, затем удалите переменную из `.env` и выполните `docker compose run --rm migrate` ещё раз.
