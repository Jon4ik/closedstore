### 2. Ошибка "Invalid value for argument `closureDate`"
**Статус:** ✅ Исправлено

**Проблема:** Frontend отправлял даты в формате "ДД.ММ.ГГГГ", но Prisma ожидал ISO-8601 формат

**Решение:**
- Добавлена функция `convertDate()` на backend для конвертации дат
- Автоматическая конвертация из "ДД.ММ.ГГГГ" в ISO-8601
- Валидация формата дат перед сохранением

**Файл:** `backend/src/modules/stores/stores.service.ts`

## Форматы валидации

### Даты
**Формат:** ДД.ММ.ГГГГ

**Примеры:**
- ✅ `01.02.2026`
- ✅ `31.12.2025`
- ✅ `15.06.2024`
- ❌ `2026-02-01` (неверный формат)
- ❌ `32.01.2026` (неверный день)
- ❌ `01.13.2026` (неверный месяц)
- ❌ `01.02.999` (неверный год)

### Телефоны
**Формат:** Международный формат с опциональными скобками, дефисами, пробелами

**Примеры:**
- ✅ `+7 (999) 123-45-67`
- ✅ `+79991234567`
- ✅ `8-999-123-45-67`
- ✅ `999 123 45 67`
- ✅ `+1 234 567 8900`
- ❌ `abc` (не цифры)
- ❌ `123` (слишком короткий)

### Email
**Формат:** Стандартный email формат

**Примеры:**
- ✅ `user@example.com`
- ✅ `user.name@company.ru`
- ✅ `test123@mail.org`
- ❌ `not-an-email`
- ❌ `@company.ru`
- ❌ `user@`
- ❌ `user@.com`

## Обновление на сервере

### Быстрая команда:
```bash
cd ~/store-reconstruction && \
git pull && \
docker compose stop backend && \
docker compose rm -f backend && \
docker compose build --no-cache backend && \
docker compose up -d backend && \
docker compose stop frontend && \
docker compose rm -f frontend && \
docker compose build --no-cache frontend && \
docker compose up -d frontend
```

### Пошагово:
```bash
# 1. Скопировать файлы
cd ~/store-reconstruction
git pull

# 2. Пересобрать backend
docker compose stop backend
docker compose rm -f backend
docker compose build --no-cache backend
docker compose up -d backend

# 3. Пересобрать frontend
docker compose stop frontend
```
