# 🔧 Решение ошибки Prisma P3005

## Ошибка

```
Error: P3005
The database schema is not empty.
```

## Причина

Эта ошибка возникает, когда:
1. База данных уже содержит таблицы (созданные через SQL скрипт)
2. Prisma пытается применить миграции
3. Prisma обнаруживает, что база не пустая, но таблица `_prisma_migrations` отсутствует или пуста

## Решение

### Вариант 1: Использовать baseline миграцию (рекомендуется)

Если база данных уже содержит таблицы, созданные через `init-db.sql`, создайте baseline миграцию:

```bash
# Сделайте скрипт исполняемым
chmod +x baseline-migration.sh

# Запустите создание baseline
./baseline-migration.sh
```

Этот скрипт:
1. Создаст таблицу `_prisma_migrations` (если её нет)
2. Добавит запись о том, что миграция `20240101000000_init` уже применена
3. Prisma больше не будет пытаться применить эту миграцию

После этого запустите проект:

```bash
./start.sh
```

### Вариант 2: Очистить базу и начать заново

Если вы хотите начать с чистой базы данных:

```bash
# Сделайте скрипт исполняемым
chmod +x reset-database.sh

# Запустите очистку
./reset-database.sh
```

Этот скрипт:
1. Удалит все таблицы из базы данных
2. Создаст миграцию из Prisma схемы
3. Применит миграции через Prisma

После этого запустите инициализацию:

```bash
./init-db.sh --sql
```

### Вариант 3: Автоматическое определение (через init-db.sh)

Скрипт `init-db.sh` теперь автоматически определяет проблему:

```bash
./init-db.sh --sql
```

Если база данных уже содержит таблицы, скрипт предложит:
- Использовать baseline миграцию
- Очистить базу и начать заново

## Подробное объяснение

### Что такое baseline миграция?

Baseline миграция - это способ сказать Prisma: "Эта миграция уже применена, не пытайся применить её снова".

Когда вы создаете таблицы через SQL скрипт (`init-db.sql`), Prisma не знает об этом. Когда backend пытается запуститься, Prisma видит:
- Таблицы существуют (база не пустая)
- Таблица `_prisma_migrations` отсутствует или пуста
- Это ошибка P3005

Baseline миграция добавляет запись в `_prisma_migrations`, говорящую Prisma, что миграция уже применена.

### Структура baseline миграции

```
backend/prisma/migrations/
├── migration_lock.toml
└── 20240101000000_init/
    └── migration.sql
```

Файл `migration.sql` содержит SQL для создания всех таблиц, а `migration_lock.toml` указывает провайдер базы данных.

### Таблица _prisma_migrations

Prisma создает эту таблицу автоматически для отслеживания примененных миграций:

```sql
CREATE TABLE _prisma_migrations (
    id                      VARCHAR(36) PRIMARY KEY,
    checksum                VARCHAR(64) NOT NULL,
    finished_at             TIMESTAMP WITH TIME ZONE,
    migration_name          VARCHAR(255) NOT NULL,
    logs                    TEXT,
    rolled_back_at          TIMESTAMP WITH TIME ZONE,
    started_at              TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT now(),
    applied_steps_count     INTEGER NOT NULL DEFAULT 0
);
```

Скрипт `baseline-migration.sh` добавляет запись:

```sql
INSERT INTO _prisma_migrations (
    id,
    checksum,
    finished_at,
    migration_name,
    started_at,
    applied_steps_count
) VALUES (
    gen_random_uuid()::text,
    '<checksum>',
    now(),
    '20240101000000_init',
    now(),
    1
);
```

## Проверка

После создания baseline миграции проверьте:

```bash
# Подключитесь к базе данных
psql -h localhost -p 5432 -U your_user -d your_database

# Проверьте таблицу миграций
SELECT * FROM _prisma_migrations;

# Должна быть одна запись с migration_name = '20240101000000_init'
```

## Альтернативные решения

### Использование prisma db push

Если вы не хотите использовать миграции, можно использовать `prisma db push`:

```bash
cd backend
npx prisma db push
cd ..
```

Эта команда синхронизирует схему Prisma с базой данных без использования миграций.

**Преимущества:**
- Проще для разработки
- Не требует управления миграциями

**Недостатки:**
- Не подходит для production
- Нет истории изменений
- Может привести к потере данных

### Ручное создание миграции

Если автоматические скрипты не работают:

```bash
cd backend

# Создайте папку миграций
mkdir -p prisma/migrations/20240101000000_init

# Скопируйте SQL из init-db.sql в migration.sql
cp ../init-db.sql prisma/migrations/20240101000000_init/migration.sql

# Создайте migration_lock.toml
cat > prisma/migrations/migration_lock.toml << EOF
# Please do not edit this file manually
provider = "postgresql"
EOF

# Создайте таблицу _prisma_migrations
psql -h $DB_HOST -p $DB_PORT -U $DB_USER -d $DB_NAME << 'EOF'
CREATE TABLE IF NOT EXISTS _prisma_migrations (
    id                      VARCHAR(36) PRIMARY KEY NOT NULL,
    checksum                VARCHAR(64) NOT NULL,
    finished_at             TIMESTAMP WITH TIME ZONE,
    migration_name          VARCHAR(255) NOT NULL,
    logs                    TEXT,
    rolled_back_at          TIMESTAMP WITH TIME ZONE,
    started_at              TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT now(),
    applied_steps_count     INTEGER NOT NULL DEFAULT 0
);
EOF

# Вычислите checksum
CHECKSUM=$(sha256sum prisma/migrations/20240101000000_init/migration.sql | cut -d' ' -f1)

# Добавьте запись о миграции
psql -h $DB_HOST -p $DB_PORT -U $DB_USER -d $DB_NAME << EOF
INSERT INTO _prisma_migrations (
    id,
    checksum,
    finished_at,
    migration_name,
    started_at,
    applied_steps_count
) VALUES (
    gen_random_uuid()::text,
    '$CHECKSUM',
    now(),
    '20240101000000_init',
    now(),
    1
);
EOF

cd ..
```

## Профилактика

Чтобы избежать этой ошибки в будущем:

1. **Для новой базы данных:**
   ```bash
   # Создайте базу данных
   psql -c "CREATE DATABASE mydb;"
   
   # Запустите инициализацию
   ./init-db.sh --sql
   ```

2. **Для существующей базы данных:**
   ```bash
   # Используйте baseline миграцию
   ./baseline-migration.sh
   ```

3. **Для разработки:**
   Используйте `prisma db push` вместо миграций:
   ```bash
   cd backend
   npx prisma db push
   ```
