**Проблема:** Таблица была перегружена информацией  
**Решение:** Реализован спойлер:

  - Информация об объекте (номер и адрес)

## Проверка БД - userName в audit_logs

**Текущее состояние:** В таблице `audit_logs` хранится поле `userName` (текстовое имя пользователя)

**Рекомендация:** Это поле можно оставить для удобства чтения логов напрямую в БД. Основное отображение имени пользователя происходит через `userId` и связь с таблицей `users`.

**Преимущества текущего подхода:**
- ✅ Быстрый просмотр логов без JOIN
- ✅ История сохраняется даже если пользователь удален
- ✅ Производительность при чтении логов

**Недостатки:**
- ⚠️ Дублирование данных
- ⚠️ Если пользователь изменит имя, в логах останется старое имя

**Решение:** Оставить как есть - это нормальная практика для audit логов.

## Обновление на сервере

### Шаг 1: Скопируйте файлы
```bash
cd ~/store-reconstruction
git pull
```

### Шаг 2: Пересоберите frontend
```bash
docker compose stop frontend
docker compose rm -f frontend
docker compose build --no-cache frontend
docker compose up -d frontend
```

### Шаг 3: Проверьте работу
1. **Таблица объектов** - создайте объект с существующим номером - должно работать
2. **Аудит** - откройте страницу аудита:

3. **Администрирование** - проверьте иконки в боковом меню
